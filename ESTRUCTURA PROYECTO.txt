Por ejemplo:
ADR-004
Decisión:
Las extensiones a procesar serán seleccionables por el usuario.
Motivo:
El flujo habitual utiliza CR3 + XMP, pero otros proyectos pueden requerir CR2, NEF, ARW u otros formatos.
Consecuencia:
El motor de movimiento no debe estar acoplado a una extensión específica.
Esto es precisamente el tipo de documentación que después te ayuda a entender por qué el software está diseñado de cierta manera.

15. Cómo quedaría nuestro concepto funcional
Creo que ya podemos establecer una primera definición:
andercal.visuals — Selector es una aplicación de escritorio para Windows destinada a localizar, verificar y trasladar archivos fotográficos asociados a una lista de identificadores, permitiendo al usuario seleccionar las extensiones que desea procesar y conservando la última carpeta utilizada y las preferencias de formatos.
Y las reglas fundamentales serían:
1. El usuario proporciona una lista de referencias.
2. El sistema extrae los identificadores fotográficos.
3. Los identificadores se normalizan y eliminan duplicados.
4. El usuario selecciona las extensiones que desea procesar.
5. El sistema busca únicamente esas extensiones.
6. El sistema informa encontrados y faltantes.
7. El sistema no ejecuta movimientos sin confirmación.
8. Los archivos procesados se llevan a /Seleccionadas.
9. El sistema recuerda la última carpeta utilizada.
10. El sistema recuerda las extensiones seleccionadas.
11. No se almacenará historial de operaciones en esta versión.
Esto ya nos da una base real para el documento de requisitos.

7. Una cosa importante al crear el repositorio
Cuando creemos el repositorio vacío en GitHub, no vamos a inicializarlo con README, .gitignore ni License desde GitHub.
Vamos a crear esos archivos localmente dentro de nuestro proyecto.
La propia documentación de GitHub contempla este flujo para publicar un proyecto local nuevo: inicializar Git, hacer el primer commit, asociar el remoto y hacer push. GitHub Docs
Así tendremos control completo desde el principio.

9. ¿HTTPS o SSH?
Para comenzar, HTTPS.
Tenemos:
https://github.com/...
en lugar de:
git@github.com:...
GitHub soporta ambos métodos. SSH requiere configurar una clave SSH; HTTPS es más sencillo para nuestro primer proyecto. GitHub Docs
Además, Git puede utilizar un administrador de credenciales para no pedirte autenticación constantemente. GitHub Docs
Más adelante, si quieres aprender SSH, lo hacemos.
