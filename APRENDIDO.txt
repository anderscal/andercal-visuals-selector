[FASE 0] CIMIENTOS, ENTORNO Y CONTROL DE VERSIONES
----------------------------------------------------------------------

1. CONTROL DE VERSIONES (GIT vs GITHUB):
   • Git:
     - Es un software local que vive en tu máquina.
     - Funciona 100% offline.
     - Su misión: registrar la historia del código a través de "snapshots" (fotos del estado del proyecto) llamados COMMITS.
   • GitHub:
     - Es una plataforma en la nube (remota).
     - Su misión: alojar copias de repositorios Git para respaldo, colaboración y portafolio profesional.
   • Flujo de trabajo esencial:
     - Código modificado -> git status (ver qué cambió)
     - git add . (preparar cambios en "staging")
     - git commit -m "mensaje" (guardar cambio en el historial local)
     - git push origin main (subir cambios a GitHub)

2. COMANDOS BÁSICOS DE VERIFICACIÓN (Terminal / PowerShell):
   • git --version
     Verifica que Git esté instalado en el PATH del sistema.
   • python --version
     Verifica la versión instalada del intérprete de Python (recomendado 3.10 o superior).

3. IDENTIDAD EN GIT (FIRMA DEL AUTOR):
   • ¿Por qué es necesario?
     Cada "commit" en Git es una firma indeleble que requiere:
     - Nombre de autor (user.name)
     - Correo electrónico (user.email)
   • Relación con GitHub:
     Si el correo coincide con el registrado en tu cuenta de GitHub, los commits se vincularán automáticamente a tu perfil y foto.
   • Comandos de consulta:
     git config --global user.name
     git config --global user.email
     git config --global --list
   • Configurado actualmente:
     user.name = anderscal
     user.email = calderonanderson78@gmail.com

4. INICIALIZACIÓN DE UN REPOSITORIO (GIT INIT):
   • git init:
     Crea una carpeta oculta '.git/' que convierte la carpeta en un repositorio bajo control de versiones.
   • git branch -M main:
     Renombra la rama por defecto a 'main', alineándose con el estándar actual de la industria y de GitHub.

5. EL ARCHIVO .gitignore:
   • Propósito:
     Evita que archivos basura, temporales, cachés compiladas (__pycache__/) o entornos virtuales (.venv/) se registren en el historial o se suban a la nube.
   • Regla de oro:
     Solo versionamos código fuente, assets necesarios y documentación. Nunca cachés ni temporales del sistema operativo.

6. EL ÁREA DE PREPARACIÓN (STAGING AREA) Y PRIMER COMMIT:
   • git status:
     Muestra qué archivos se han modificado, creado o eliminado.
   • git add . (o git add <archivo>):
     Mueve los archivos al "Staging Area" (el sobre cerrado antes de enviar la carta).
   • git commit -m "mensaje":
     Toma una fotografía del estado actual de los archivos en Staging y la guarda en el historial permanente.
   • Convención de mensajes de commit (Conventional Commits):
     - feat: nueva funcionalidad o estructura
     - fix: corrección de errores
     - docs: cambios en documentación

7. REPOSITORIO REMOTO Y VINCULACIÓN CON GITHUB:
   • remote origin:
     'origin' es el alias por defecto que le da Git a la URL remota de tu repositorio en GitHub.
   • git remote add origin <URL>:
     Conecta el proyecto local de tu máquina con el repositorio en la nube en GitHub.
   • git remote -v:
     Verifica a qué direcciones web apunta tu repositorio (fetch/push).
   • git push -u origin main:
     - 'push': sube las versiones guardadas (commits) hacia GitHub.
     - '-u' (upstream): establece un vínculo permanente entre tu rama local 'main' y 'origin/main', para que en el futuro solo tengas que escribir 'git push'.

[FASE 1] MOTOR CENTRAL DE ARCHIVOS (CORE LOGIC)
======================================================================

1. EXPRESIONES REGULARES (REGEX) EN PYTHON:
   • ¿Qué es RegEx?
     Un lenguaje de patrones para buscar, extraer o validar combinaciones específicas de caracteres dentro de un texto.
   • El módulo 're' de Python:
     - re.findall(pattern, string): Encuentra todas las coincidencias del patrón en el texto.
   • Patrón de extracción de códigos de 4 dígitos:
     - (?<!\d)\d{4}(?!\d)
     - '\d{4}': busca exactamente 4 dígitos seguidos (0000 al 9999).
     - Lookarounds (?<!\d) y (?!\d): asegura que no extraiga 4 dígitos de un número de 5 dígitos (ej. no extrae 7644 de 17644).

   • Caso Borde Detectado (Fechas vs Códigos):
     - Problema: En tablas de Excel con fechas (ej. '9/28/2026'), el año '2026' era interpretado como un código fotográfico falso.
     - Solución: Aplicar una fase previa de desinfección mediante la RegEx '\b\d{1,4}[/.-]\d{1,2}[/.-]\d{1,4}\b' para eliminar fechas completas antes de buscar los códigos.

2. MANEJO DE RUTAS CON PATHLIB Y SIDECARS XMP:
   • pathlib.Path (Librería estándar de Python):
     - Sustituye a os.path por una manipulación orientada a objetos de rutas del sistema operativo.
     - .is_dir(), .is_file(), .iterdir(), .name
     - .lower(): permite búsquedas insensibles a mayúsculas/minúsculas (.CR3 vs .cr3).
   • Convención de Sidecars XMP:
     - XMP Simple: _MG_8009.xmp
     - XMP Doble: _MG_8009.CR3.xmp
     - Solución en scanner.py: Validar mediante name.lower().endswith(ext_lower), garantizando la captura de ambas convenciones.

3. VALIDADOR DE DIAGNÓSTICO E INTEGRIDAD DE DATOS (validator.py):
   • Principio de Seguridad Primero (Fail-Safe):
     - La aplicación no debe arriesgarse a mover/copiar parcialmente una selección si falta algún archivo o si hay colisiones.
   • Reporte de Diagnóstico Estructurado:
     - unique_codes: códigos extraídos sin duplicados.
     - found_counts / missing_counts: resumen numérico por formato.
     - missing_details: diccionario con la ubicación exacta de los archivos faltantes por código y extensión.
     - ambiguous_details: detección de colisiones de nombres (ej. Canon vs Nikon en la misma carpeta).
     - files_to_process: lista definitiva de objetos Path validados para ser operados.
     - is_valid_for_operation: bandera booleana global que bloquea o habilita la acción final.

4. GESTOR DE OPERACIONES DE ARCHIVOS Y NOMBRES ÚNICOS (mover.py):
   • shutil.copy2 vs shutil.move:
     - shutil.copy2: Copia los datos y conserva metadatos originales de fechas (Creación y Modificación).
     - shutil.move: Traslada el archivo en el sistema de archivos.
   • Validación de existencia de carpetas:
     - mkdir(parents=True, exist_ok=True): Garantiza la existencia de /Seleccionadas sin fallar si ya existía previamente.
   • Función get_unique_destination_path:
     - Si 'foto.CR3' ya existe en /Seleccionadas, asigna automáticamente 'foto_1.CR3', 'foto_2.CR3', etc.
     - Garantiza cero pérdidas de información o sobrescrituras involuntarias.

[FASE 2] PRUEBAS AUTOMATIZADAS DE INTEGRACIÓN (PYTEST)
======================================================================

1. SUITE UNIFICADA DE PRUEBAS CON PYTEST:
   • ¿Qué es pytest?
     El framework estándar en la industria de Python para ejecutar pruebas unitarias y de integración.
   • Instalación de dependencias externas (pip vs python -m pip):
     - En Windows, si 'pip' no está directo en el PATH global, se invoca a través del intérprete ejecutable:
       python -m pip install -r requirements.txt
     - Ventaja de 'python -m pip': Garantiza que los paquetes se instalen exactamente en el Python activo en la terminal.
   • Descubrimiento automático (Test Discovery):
     pytest detecta automáticamente cualquier archivo que comience por 'test_*.py' y ejecute sus funciones 'test_*()'.
   • Comando de ejecución:
     python -m pytest -v (modo 'verbose': muestra el detalle de cada prueba pasada o fallida).
   • Pruebas End-to-End (E2E):
     Validan la tubería completa (Parser -> Scanner -> Validator -> Mover) en directorios temporales aislados (tempfile).

[FASE 3] PERSISTENCIA LOCAL Y CONFIGURACIÓN (JSON)
======================================================================

1. GESTOR DE PREFERENCIAS Y FORMATOS (settings_manager.py):
   • Objeto json en Python:
     - json.load(f): Lee y convierte texto JSON a un diccionario o lista nativa de Python.
     - json.dump(obj, f, indent=2, ensure_ascii=False): Escribe un diccionario de Python como un archivo JSON formateado y legible.
   • Estrategia de Carga Segura (Fallbacks / Resiliencia):
     - Si 'settings.json' o 'formats.json' no existen o están dañados, el sistema no colapsa: carga los valores por defecto (DEFAULT_SETTINGS) y regenera los archivos automáticamente.
   • Extensibilidad por el usuario:
     - La función add_custom_format() permite agregar nuevos formatos (ej: 'PSD', 'TIFF') dinámicamente sin modificar el código fuente.

[FASE 4] INTERFAZ GRÁFICA MODERNA (CUSTOMTKINTER)
======================================================================

1. ARQUITECTURA DE LA APLICACIÓN DE ESCRITORIO (src/gui/ & src/app.py):
   • CustomTkinter vs Tkinter Clásico:
     - CustomTkinter proporciona componentes visuales modernos con bordes redondeados, escalado DPI, tema oscuro ('Dark') y paleta de colores personalizada.
   • Componentes principales:
     - CTkEntry y filedialog.askdirectory(): Explorador de archivos nativo de Windows.
     - CTkTextbox: Caja de texto de entrada para pegar listados de Excel o texto.
     - CTkCheckBox dinámicos y Botón '➕ Agregar extensión':
       Permite al usuario añadir nuevos formatos personalizados (ej: PSD, TIFF, PNG) en tiempo real, registrándolos en formats.json y agregando el checkbox dinámicamente.
     - Modal PreviewDialog (CTkToplevel): Ventana emergente que bloquea la ventana principal (.grab_set()) exigiendo confirmación explícita con lista detallada antes de mover/copiar.
   • Bucle de Eventos (.mainloop()):
     - Ciclo continuo en src/app.py que escucha los clics, entradas de texto y redibujado de la interfaz.

   • Centrado Dinámico de Ventanas:
     - Cálculo de dimensiones de pantalla mediante winfo_screenwidth() y winfo_screenheight() para posicionar la ventana perfectamente centrada (+x+y) en monitores de cualquier resolución.
   • Flexibilidad de Procesamiento Parcial con Advertencia (UX Mejora de Campo):
     - Situación: Si el usuario selecciona extensiones opcionales (ej: ACR o XMP que no aplican a todas las fotos), la aplicación no debe bloquear la operación.
     - Solución: El botón '⚠️ VISTA PREVIA Y PROCESAR (N ARCHIVOS ENCONTRADOS)' se habilita en color naranja si hay archivos encontrados (can_process = True), permitiendo al usuario revisar el modal con la advertencia explícita y proceder según su criterio.

[FASE 6] EMPAQUETADO A EJECUTABLE DE WINDOWS (.EXE)
======================================================================

1. EMPAQUETADO CON PYINSTALLER:
   • ¿Qué hace PyInstaller?
     Analiza el código Python, identifica todas sus dependencias (CustomTkinter, Pillow, etc.) y compila la aplicación en una estructura de ejecutable autónomo.
   • Modos de ejecución:
     - --noconsole (o --windowed): Oculta la consola negra de comandos para que la aplicación abra únicamente su interfaz de usuario.
     - --clean: Limpia cachés temporales previas de empaquetado antes de generar el nuevo build.
   • Carpetas generadas:
     - build/: Archivos temporales de análisis de compilación (excluidos por .gitignore).
     - dist/: Ubicación donde se almacena la carpeta ejecutable lista para distribuir ('dist/andercal.visuals - Selector/').
